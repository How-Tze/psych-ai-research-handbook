5  第2章 AI 已经从聊天框进入工作环境

作者

Hao Xie

本章问题：为什么同一个模型在不同产品里能做完全不同的事？

同一个模型，有时只能回答你粘贴进去的问题，有时却能搜索网络、读取整个文件夹、修改代码并运行测试。差异不只来自模型“聪不聪明”，还来自它被放在怎样的工作环境里。

5.1 2.1 模型、工具、运行框架与 Agent

概念 最简单的理解 研究中的例子
模型（Model） 负责理解、生成和推理 解释统计输出、比较理论解释
工具（Tool） 让模型访问外部能力 搜索、PDF/表格读取、Python/R、终端、文件操作
运行框架（Harness） 决定模型看得到什么、能调用什么、有什么权限、怎样记录和何时停下 项目空间、代码代理工作区、带文件和工具的研究环境
Agent 在运行框架的边界内根据中间结果继续行动 检查文件 → 修改副本 → 运行测试 → 遇到边界请求确认

本手册把这一层称为“运行框架（Harness）”。可以把它理解成 AI 的工作台：台面上有什么材料、接了哪些工具、允许哪些动作、哪些步骤需要确认，都会改变 AI 实际能做的事。判断一个 AI 环境时，先问三件事：它能看见什么、能做什么、会留下什么记录。Harness 是当前 agent 工程中常用的概念之一，但不是跨厂商统一的产品分类。

5.2 2.2 我现在应该打开什么

你现在要做什么 更适合的工作环境 你实际会看到什么 先注意什么
讨论理论、解释概念、改一小段文字 普通对话 回答、改写、代码片段 正式依据仍回到真实材料
检索领域、追踪公开来源 联网搜索/深度研究类环境 带来源的候选文献或事实汇总 关键主张回原始来源核对
围绕同一研究持续读多份材料 项目型工作区（Project/Workspace 等） 可复用明确加入项目的文件、知识或说明；跨对话上下文规则因平台而异 项目里“有文件”不等于它是当前有效版本
读取、修改并运行代码 代码代理（Code Agent）/本地代码环境 目录、diff、终端输出、测试结果 先只读或改副本，再增加权限
跨文件、跨工具连续执行多步任务 Agent + 合适的运行框架 阶段性产物、工具调用、确认请求 先写清可见材料、权限和停止条件

这些名称只是工作环境的分类，不是产品认证。同一个产品可能同时提供普通聊天、项目空间和 Agent 模式。选择时先看任务需要哪些材料和工具，再看具体产品。

5.3 2.3 五分钟能力自检

  • 上传一份无敏感信息的 PDF 或表格，要求它指出具体页、列或字段：如果可以，至少具备文件读取能力。

  • 新开一次对话或任务后，看它能否继续访问你明确加入项目来源、知识库或固定说明的材料：如果可以，说明具备某种持续项目材料能力。不要假设所有平台都会自动共享旧聊天上下文。

  • 要求它搜索公开资料并返回可核查来源：如果可以，可以用来找候选文献和方法资料。

  • 让它列出代码目录并读取脚本，同时明确“不要修改”：如果可以，具备文件系统级代码审查能力。

  • 允许它在副本中改一处代码、运行测试并给出 diff：如果可以，说明当前环境具备有限写入和执行能力。

不要把 Agent 当成成熟度指标。规则固定的转换通常交给脚本更稳妥；理论探索、方法争议和构念判断则适合保留在人机协作中。任务确实需要根据中间状态跨文件或工具行动时，再考虑 Agent。

本章应用：选你今天的一项任务，先问“AI 需要看见什么、调用什么”，再确认当前环境是否真的具备这些能力。够用即可，不追求功能最多。
