重复工作怎样做好：对话、脚本与 Agent 的分工

v1.3 · 2026-10-16

作者

Hao Xie

第一次让 AI 帮你整理结果，可能只需要一张表和一句说明。第二次改稿，你又解释了一遍哪些列要保留、系数保留几位小数、哪些结论不能自动补。到了第三次，值得问的就不只是“怎样把要求说清楚”，还包括：哪些事情已经足够确定，可以不再每次重新讨论？

把这些工作固定下来，可以让你把注意力留给真正变化的部分。脚本可以负责重复的计算或转换，AI 帮助理解新材料、查找受影响的位置，研究者处理新的解释和方法选择。它们可以在同一项任务里配合，也可以分别使用。

先认清两个名字：脚本是一份能反复运行的程序，例如读表后按规定格式生成报告；Agent（智能体）则是能使用工具、根据中间结果继续做事的 AI 助手。Qwen Code、Codex、Claude Code 是具体例子，产品介绍见工具章。读本章时，可以先比较已经生成的文件，再跟着说明练习运行。

本章沿用项目连续性章的两轮报告，比较几种做法。配套脚本已经实际运行，Agent 对话与任务安排则为教学编写。

同一项任务，哪些部分每次都一样

假设你经常需要把确认结果表变成供组会讨论的文字。完整任务至少包含两类不同工作。一类已经很明确：读指定列、按约定顺序排表、保留三位小数。另一类要看具体研究：这些结果支持怎样的解释，哪些限制值得写进讨论。

可以先请 AI 帮你把最近两次工作放在一起比较：

下面是两次任务说明和确认后的结果。请指出哪些步骤完全相同，哪些取决于本次研究判断。对相同部分，说明能否用固定规则表达；对变化部分，举例说明为什么还需要讨论。

在本例中，列选择和数字格式可以固定；主分析与比较分析的地位需要有事先依据；“结果是否稳健”则不能仅靠系数同号自动生成。可以先把数字整理固定下来，把解释留到每次看过结果后再讨论。

先保存一份有效说明，让人也能照着做

第一次任务还不熟悉时，普通对话很方便。你可以给 AI 一段结果，让它解释、起草，再根据问题追问。完成后，把反复需要解释的部分保存下来：

从指定的确认结果表整理报告。保留本次要求的分析规则、纳入记录数和两项系数；数字按约定精度显示。数字描述与解释建议分开。缺少列或分析结果时指出缺项，不自行推算。输出到新的候选文件，并说明使用的输入。

这已经是一份可复用说明。下一次只要补上当前文件和报告范围，就不用重写全部要求。你也可以加一个已确认的短例子，让 AI 更容易理解输出形式。

如果任务需要按几个步骤完成，就把顺序写清楚。例如，先整理表，再写数字段，最后另读现有讨论，提出需要调整的句子。这种简短的操作说明可以由人执行，也可以交给 AI，保存为普通文档就能复用。

复用时仍要检查是否适用。旧说明若是为普通回归写的，遇到另一类模型，就要重新讨论该报告哪些量。固定下来的应是已经理解的规则，不能让旧模板替你决定新研究。

把确定的转换交给脚本：实际运行两轮

配套的 build_report.py只做一件小事：读取本手册规定格式的确认结果表，生成一张表和一段数字描述。文件名末尾的 .py 表示它是用 Python 编写的程序；让计算机执行其中的步骤，就是“运行脚本”。它不调用模型，不重新拟合分析，也不判断结果意味着什么。

你可以先比较两个已经生成的文件，不必先安装环境：

本轮选择 实际产物 发生了什么变化
只练习主分析片段 第一轮数字稿 21 条记录，压力 0.364、反刍 0.343
纳入同表已有的比较结果 第二轮数字稿 在保留主规则的同时增加比较规则：15 条记录，压力 1.081、反刍 0.720

两次运行使用同一个输入文件，改变的是报告范围：先练习报告主分析，再把比较分析加入完整稿件。最终报告应包含研究问题和既有约定要求呈现的结果。

脚本输出还说明了本次模式和实际输入的文件指纹。这样，看到两个数字稿时，可以检查它们究竟用了同一份结果，还是输入已经变化。文件指纹只是识别材料的一种办法，并不说明材料正确；日常小任务也可以先用明确的文件位置和版本说明。

运行方法见教学项目入口。若让 AI 协助操作，可以这样交代：

请读取配套运行说明，使用确认结果表生成两轮报告。先核对输入和脚本用途，按说明运行，检查两个输出与表格一致。使用新的输出位置，不覆盖参考文件。最后告诉我实际执行了什么，以及哪些内容没有经过这个脚本检查。

完成后，你应当能看到文件和其中的数字，而不只是“已成功处理”的回复。这个脚本遇到缺少字段、未知规则或非有限系数会停止，遇到已有输出也会要求换一个文件名。它仍无法识别一个格式正确、但来自错误模型的表；这种问题要回到分析过程核对。

保存好脚本后，同类转换就能直接运行。以后需要修改格式，可以请 AI 调整相应步骤，再检查新输出。这样，前一次写好的程序会继续为后面的工作节省时间。

哪些工作适合保存为 Skill

有些任务无法完全写成固定转换，却有相对稳定的做法。例如，检查讨论是否把横断关联写成因果，需要读懂具体句子；同时，你又希望每次都结合研究设计、指出原句、解释问题并给出保留原意的改法。

这时可以把方法说明、一个合格例子、一个容易误判的例子及输出要求一起保存。在支持这项功能的 AI 工具里，这些内容可以组织成 Skill（技能）。例如，调用一项“讨论段检查”技能时，AI 就能读取其中的检查步骤，参照合格段落和容易误改的反例处理新稿。具体怎样保存和调用，要看所用平台的说明。

一个有用的检查说明，应当承认研究之间的区别。例如，不能把所有“影响”一律删成“相关”：文章可能正在描述随机实验，也可能是在介绍某个理论的主张。你可以让 AI 先解释句子在当前语境中的含义，再建议修改。

复用之前，挑几段你能判断的材料试用，看看它能否发现问题、会不会误改正确句子、遇到依据不足时会怎样处理。规则改变后，也要重看这些例子。保留试用中发现的问题和修改，才能知道这项技能在哪些情况下有用，哪些地方还要自己检查。

当下一步取决于中间结果，再考虑 Agent

一个固定脚本按既定规则执行；Agent 则会在允许的范围内，根据看到的情况选择下一步。例如，它读到项目说明，找到指定结果表，运行报告脚本，发现某个输出缺失后检查原因，再查找正文中的相关段落。

这时，研究者不必逐步发出“现在打开这个文件”“接着运行这条命令”。你可以一次交代一个完整而有限的任务：

请根据项目入口，把确认结果更新为一份新的组会候选稿。可以读取指定结果和当前文稿、运行已有报告脚本、在候选目录中写入修改。完成数字核对，列出涉及解释的改动供我审阅。路径错误或缺少普通输出目录可自行修复；若发现两份结果都被标为当前有效，或需要改变分析规则，指出冲突后再继续讨论。

这段说明规定了完成什么，也区分了它可以自行处理的问题和需要重新判断的事情。Agent 应把任务推进到一个可以审阅的结果，不必每做完一个机械步骤都回来请示；研究者也不用在开始时预想所有点击和命令。

Anthropic 的工程文章《Building effective agents》进一步解释了两种安排：由程序预先规定步骤，以及由 Agent 根据中间结果选择下一步动作。原文

本手册说的“研究工作流”，包含研究者、普通对话、脚本和其他工具怎样共同推进研究；Agent 是其中一种可选工具。工程文档有时把 workflow 专指由代码预先安排的流程，阅读时结合上下文理解即可。

深入讨论、执行与审阅怎样交接

一次复杂任务可以先进入讨论：比较方案、核对方法依据、判断哪些限制影响结论。适合投入较多推理的地方，是存在真正取舍的问题，例如“这项比较改变了哪些解释”“新增测量能否区分两个理论”。这里也需要给足原始材料，不能只期待更强的模型替你补全缺失信息。

形成决定后，把它转成执行所需的简短说明。例如，本例的决定可以是：

同时呈现两种计分规则；主次地位暂按教学规格保留；讨论需说明系数大小的变化。执行任务是生成表和数字段，找出讨论中需要改写的句子，保存候选并完成数字核对。不得新增模型或替换原结果。

执行者据此完成文件操作、运行和检查。结束时，把候选文件、实际完成的检查和未解决的问题一起交回。研究者随后审阅的重点，是解释是否合适、修改是否回答了研究问题，而不是重新指挥它搬运每个数字。

这三类工作可以在同一工具里进行，也可以交给不同环境。切换时要带走已经确认的决定和所需材料，不必复制全部聊天。若任务已经说清楚，执行又没有遇到新的方法分歧，就可以连续完成；如果输入推翻了原先假设，则应把具体冲突带回讨论。

选择工具时，可以看任务需要怎样的判断。核对多份材料、比较复杂方案时，更强的推理能力可能有用；规则明确的转换，则适合交给已经检查过的程序。试着用一项实际任务比较所花的时间、结果质量和检查负担，再决定以后怎样分工。

多个 Agent 什么时候值得使用

假设候选稿已经形成，一项工作是逐条核对文献链接，另一项是按给定输入复算表格。它们需要的材料不同，结果也容易分别检查，可以考虑并行。反过来，分析规则还没决定时，让一个 Agent 改代码、另一个同时写结论，很容易让两者依赖不同假设。

开始前可以给每项任务写几句：使用哪份输入、交付什么、允许改哪些文件、怎样算完成。若两个任务都需要改同一份正文，就安排顺序或在不同候选副本里工作，再由一个明确负责整合的人或执行者汇总。

所谓阶段安排，可以只是这次讨论的几项约定：本轮要完成什么、哪些判断已经确定、哪些问题出现时需要重新讨论。只有当工作经常跨人、跨会话或涉及重要修改时，才值得把这些约定固定成更正式的任务文件。

并行可能减少等待时间，但还会增加整合与复核工作。第二个 Agent 可以提供新的检查角度，却不是第二份独立证据。两个模型都把 24 条原始记录写成分析样本，仍会一起出错；核对本例计分规则和实际输出，才能发现分析记录是 21 条。

用做出来的结果判断，是否真的省了工作

试用一种新安排后，回顾几个具体问题：同类任务再次出现时，哪些解释已经不用重复；错误是否更容易定位；结果能否进入后续研究；为了维护这一安排又增加了多少工作。

如果每次输入都完全不同，调整脚本的时间比手工整理还多，就可以继续用对话与人工处理。如果一个步骤只是读取已知列和转换格式，就交给脚本。根据这些实际结果调整做法，保留最能帮助当前项目的部分。

练习：给自己的重复任务选一种做法

选最近实际重复过的一项工作，把一份原始输入、确认后的输出和你曾经修改它的理由放在一起。请 AI 比较下面几种方式，再由你选一种试用：

做法 你需要检查什么
继续普通对话 每次都变化的内容是否真的需要讨论
保存任务说明或简短步骤 是否减少了反复解释，又能容纳研究差异
写一个脚本 规则是否明确，输出是否能按输入核对
保存为 Skill 方法能否复用，能否处理反例和“不知道”
交给 Agent 连续执行 它是否需要按中间状态行动，任务终点是否清楚

随后再做第二次，比较实际结果。你可以像本章一样只固定一个小步骤，把其余工作留在研究讨论中。只要这项安排使下一次更容易开始、完成和检查，它就已经为你的工作流带来了具体改进。核验、隐私与恢复章接着用同一个报告脚本，演示程序正常完成却读入错误副本时，怎样发现问题并恢复。
