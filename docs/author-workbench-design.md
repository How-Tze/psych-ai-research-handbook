# 私人作者工作台：技术路线与实施规格

日期：2026-10-18。状态：设计候选，交付集中审阅；功能尚未实现。

用户已确认：编辑可随时保存，在下一轮更新时集中合并；入口必须方便；按直接修改、私人批注、随手记、AI 整合的顺序推进；本次不考虑公开评论。当前授权覆盖技术设计、经验总结和必要治理文件修改，不包含安装、功能实施、合并 main 或发布。

## 1. 交付目标

在现有两站之上增加一个共用的私人作者工作台。作者在阅读中改字、给段落或章节留意见，也能快速记下跨项目想法。系统保存这些内容及其上下文；下一轮已获授权的更新任务读取它们，把作者修改与 AI 修订一起整合到候选版。

首版面向当前 Windows 电脑上的单一作者，使用本机浏览器和两个本地仓库。沿用 Quarto、main 源码和 gh-pages 发布体系。主手册 v1.3、指南 v0.12 及历史标签、资产保持冻结。本功能有独立的工具版本，不据此宣布新的正文版本。

核心约定：**保存记录、预览草稿、整合源码、正式发布是四个不同动作。保存不触发后三项。**

## 2. 入口：安装一次，日常从两个地方进入

### 2.1 桌面和开始菜单

安装后提供“心理学 AI 手册·作者工作台”快捷方式。打开后自动启动或复用本机服务，在默认浏览器中恢复上次的项目、章节和阅读位置。首页同时提供主手册、动态指南、全部待处理意见和“记个想法”。

作者不需要输入命令、记住端口、寻找源码、先打开 Agent 对话或选 Git 分支。首次运行自动探测两个仓库和 Quarto；只有探测失败时才显示目录选择或缺失依赖的具体说明。路径存入私人配置，不硬编码作者机器路径到源码。

### 2.2 从当前阅读页面进入

两站当前页面的目录区或页脚增加“作者模式”入口。用户主动点击后，将项目、页面路径、标题锚点和阅读版本交给 Windows 启动器，由启动器启动工作台并打开对应章节。

拟用协议：`psychauthor://open?project=handbook&page=chapters%2F05-literature.html&anchor=...&build=...`。这些字段只决定打开哪里；不能携带写入、删除、执行命令或发布操作。

入口保持小而可见，不需要作者先寻找登录页。不采用“网页猜测是否安装了程序”作为必要流程。浏览器可能显示“打开外部应用”确认；尊重正常确认，不承诺每个浏览器都能免提示。

公开入口需要一次单独获批的网站技术部署。在此之前，安装包提供“在作者模式中打开”的书签入口，读取当前页面网址并启动同一协议；桌面入口始终可用。书签能力在 Chrome/Edge 实测，不能默认 Codex 内置浏览器也允许它。

### 2.3 启动失败与浏览器差异

- 启动器先检查已有服务身份和健康状态，再决定复用或重启。端口由程序管理，不把固定 localhost 地址作为唯一入口。
- 外部协议被浏览器限制时，页面提供“复制本页地址”；作者打开桌面工作台后粘贴，仍自动定位章节。程序不主动读取剪贴板。
- 未安装时显示简短安装说明；安装包地址在实际交付后填写，不提前放置假下载。
- 第一次生成本地阅读副本可能需要等待，界面显示进度。以后优先打开有版本记录的缓存；缓存旧于草稿时明确显示，不能显示“已更新”。
- 默认不设置开机自启。启动器以后台方式运行服务，不弹终端窗口；卸载仅清理本工具注册项，私人记录默认保留。

验收必须从“服务已停止”开始，验证桌面启动和页面跳转，而不能只在开发服务器已经运行时测试。

## 3. 作者界面与保存语义

工作台使用原站点的阅读布局，增加顶部状态和右侧编辑面板。推荐状态文字：“基于 v1.3 · 3 处待合并修改”“正在保存”“已保存到本机”“预览尚未刷新”。两站在工作台内切换，分别保留版本与位置。

| 动作 | 用户输入 | 保存内容 | 后续行为 |
| --- | --- | --- | --- |
| 改这段 | 作者确定的替换文字 | 原文、替换稿、来源位置与版本、修订记录 | 默认纳入下一轮，按作者原文整合 |
| 留批注 | 针对选中文字的要求或问题 | 引文、上下文、批注与意图 | 默认下一轮处理，可改为先记下来 |
| 本章改进 | 全章目标或结构意见 | 章节、意见、意图 | 在下一轮写作中综合处理 |
| 记个想法 | 一句话即可 | 当前项目/页面或跨项目范围、想法 | 默认先记录，不直接成为执行指令 |

普通段落点击“改这段”后在侧栏编辑，保留原文对照、撤销、保存状态。输入短暂停顿后事务保存；“完成”结束本次编辑，但不改项目源码。快捷键只是补充，全部动作都有可见按钮并支持键盘操作。

首版优先覆盖普通段落和简单列表。含行内格式时保留链接、强调、引用等语法；不能可靠映射的公式、复杂表格、代码或嵌套块可留批注，或打开已定位的原始段落片段编辑。不要将整页 HTML 反向转换为 Markdown。复杂编辑也保存为待合并稿；若以后接外部可视化编辑器，只打开隔离副本并导入差异，不能指向正式源码。

“查看我的修改”显示私人的替换稿覆盖效果；“生成完整预览”才在隔离副本中应用修改并调用 Quarto。轻量显示和 Quarto 最终预览要有清楚的状态区别。完整预览失败不影响记录保存，可继续修改并保留上次成功预览。

## 4. 选定的实现结构

本节是拟采用的技术路线，待本设计获准后实施。版本号在实现起点锁定并实际验证，不把本机偶然存在的运行环境当作发行依赖。

| 部件 | 拟用技术 | 职责 |
| --- | --- | --- |
| 作者界面 | TypeScript、普通 DOM/CSS，Vite 构建 | 阅读壳、侧栏、保存状态、差异、收件箱；首版无需大型前端框架 |
| 本机服务 | Python、FastAPI/Uvicorn，单实例 | 项目读取、保存、版本检查、预览队列、批次导出 |
| 私人存储 | Python sqlite3 + SQLite | 事务、修订历史、批次状态、备份和恢复 |
| 阅读与预览 | 现有 Quarto + 作者专用配置/标记 | 从隔离副本生成阅读页面和段落映射，不改正式构建配置 |
| Windows 启动与打包 | 同一 Python 启动器，PyInstaller 目录式打包 | 带运行时的应用、快捷方式、用户级协议注册、单实例转交 |
| 下一轮整合 | 工作台自带命令行接口，供本地执行 Agent 使用 | 导出选定意见、核对精确修改、生成整合结果；无内置模型调用 |

工具源码拟维护在主手册 `tools/author-workbench/`，作为出版维护工具，而非正文示例。指南只保留页面入口和项目适配配置，两库共用一个安装包、一个记录库和一份实现。此目录为计划位置，本轮未创建实现。两库的 `AGENTS.md` 仍分别适用，工作台配置不能授予新的正文或发布权限。

运行时不依赖 Codex 缓存目录里的 Python/Node。前端在打包前生成，作者机器无须安装 Node；应用包含 Python 运行时。Quarto 作为明确的外部依赖探测和提示。打包与协议注册先在 Windows 实测；不承诺未测试的 macOS、Linux 或手机支持。

Windows 协议在当前用户范围注册，安装器检查既有同名注册，避免覆盖其他程序。普通 Win32 注册方案与使用 Windows App SDK 的方案不同，首个工作包验证选用的用户级注册、参数转交和卸载行为，不把 WinUI 示例直接套到 Python 程序。

## 5. 私人数据和版本记录

默认数据目录建议为 `%LOCALAPPDATA%\PsychAI\AuthorWorkbench\`，其中保存数据库、用户配置、源码快照、批次导出和备份。预览另放 `cache/`，可以重建。应用更新和清理缓存不能删除编辑记录。

| 对象 | 必需信息 |
| --- | --- |
| 项目 | 固定项目 ID、仓库真实路径、公共网址、允许的页面/来源映射 |
| 原文快照 | 项目、文件相对路径、来源提交/标签（若已知）、文件字节哈希、原文、是否含未提交改动 |
| 编辑记录 | 唯一 ID、类型、范围、作者意图、快照 ID、段落位置、原文引文和前后文、替换稿或意见、时间、修订号 |
| 整合批次 | 批次 ID、所选记录的精确修订号、目标任务/分支/基线、每项处理结果和证据 |

“第几行”只用来辅助定位。原文快照与上下文才是后续判断旧批注的依据。正文被移动或重写后，系统可以提出定位候选；不能把模糊匹配当作自动覆盖的依据。

用户主要看到“待处理、已纳入本轮、已整合、暂缓、已撤回”。输入中的草稿另存。记录修订与任务状态分开：AI 处理旧修订时，作者新写的修订继续待处理，不能跟随旧修订一起标为完成。

采用短事务、修订号条件更新，防止多标签页相互覆盖。保存失败保留输入并明确显示；只有事务提交成功才显示“已保存”。提供撤销记录而非直接抹掉历史。浏览器缓存只救回未完成输入，数据库是私人记录的持久来源。

数据库通过 SQLite 备份接口生成一致快照，不能直接复制仍在写入的数据库文件。默认保留滚动备份；提供一键导出包含记录、原文快照和版本信息的恢复包，以及恢复演练。恢复应保留现有库，先校验后切换。作者可选另一个备份位置；同一磁盘上的副本只能应对误操作，不能当作异地备份。跨设备同步不在首版范围。

私人目录不进公共 Git 仓库，也不放在 `.qa/`。将来落入 `tasks/` 或 `DECISIONS.md` 的只是经过范围筛选的执行任务与长期决定，不自动公开整套原始意见。

## 6. 阅读页面如何可靠对应源码

不能假设 Quarto 为每个 HTML 段落提供了可逆的源文件坐标。该部分是首版的主要技术验证点。

1. 为两个项目读取实际导航和页面清单，建立“公开路径—源文件”的显式映射；保留旧地址与标题别名。无法映射时打开章节选择，保留原网址和意见。
2. 对读取到的源文件保存原始字节快照；如来自有未提交改动的工作目录，明确记录，不能冒称某个冻结标签的文本。
3. 对支持的正文区块计算精确源码范围和哈希。边界扫描识别 YAML、围栏、提示框、列表、表格等结构；只有已通过解析核对的区块开放直接编辑。未知结构保留批注能力。
4. 在隔离源副本中加入作者专用标记，经 Quarto 输出对应区块 ID。标记过程保留语法结构；渲染后核对文字、链接和目标区块。标记映射只是该快照内的位置，不承诺跨重写永久稳定。
5. 点击正文时以区块 ID 查询原始源码范围，局部修改写入记录库；后续物化预览从原文快照应用变更，未修改范围的字节不变。禁止全页 HTML 回转、全局字符串替换和凭行号覆盖。
6. 跨段选择可以立即留批注；直接改写需要显示涉及的各个区块。首版不静默把跨段选区转换为一个段落。

首个验证样本应同时包含中文重复句、链接、强调、引用、列表、提示框、数学公式、复杂表格及旧标题定位。无法可靠处理的结构降级为定位后的源片段或批注，不假装已支持可视化往返。

从线上页面进入时，应携带公开构建标识；源码与阅读版本不一致时显示差异，允许选择对应快照。旧页面无构建标识时，不猜测它等于本地 HEAD：显示“线上版本未识别”，以已标明版本的本地正文继续编辑，原网址可附在意见中。

## 7. 预览隔离与本机边界

本机服务仅监听回环地址。启动器取得一次性启动凭据，浏览器交换为本次会话凭据；长期凭据不放在公共链接、仓库或日志中。接口校验 Host、Origin、会话凭据、项目白名单和规范化路径；外部网页调用协议只能请求打开界面，不能据此修改文件。

首版使用当前 Windows 用户下的私人安装与本机会话，不另建网站账号。公开的“作者模式”链接只是启动入口，点击它不会取得作者的记录或写入权限。以后若加入远程访问，需要独立设计身份认证，不能沿用本机身份假设。

阅读预览在独立的只读本机来源中展示，与编辑 API 隔离。阅读页向作者界面只报告选区和导航，校验来源窗口及消息类型；不把写入凭据交给 Quarto 页面或其中的演示脚本。仅隐藏编辑按钮不构成权限控制。

隔离副本只复制构建必需的明确文件，不复制 `.git`、私人记录、凭据、整个临时目录。拒绝越过项目根目录的路径及链接。预览命令固定且以参数数组执行；保存记录不执行任意代码。当前两站正文无需重新执行研究代码，作者预览关闭代码执行及不必要的项目钩子；需要执行的新内容交给另行授权任务。不得修改原项目全局设置来达到隔离效果。

首次构建保留全书引用所需的上下文，随后缓存已验证的页面和资源。可安全单页渲染时只更新当前页；标题、导航、参考来源或跨章引用发生变化时重建所需范围。每份预览携带基线哈希和记录修订列表，构建期间新保存的意见保留，不能被旧构建完成事件误标为已展示。

上述措施随实现测试，不额外给作者增加日常确认步骤。首版没有远程监听、公开登录、付费模型调用或后台定时改稿。

## 8. 下一轮如何合并作者修改和 AI 修订

### 8.1 启动一次明确的整合批次

作者发起下一轮更新后，执行 Agent 读取项目当前阶段及适用规则，通过工作台的本地接口获取待处理记录。按本轮批准的范围选择项目和记录，把所选修订号固化为批次；范围外意见保留，不因读取到就自动扩展任务。

工作台拟提供 `prepare-batch`、`export-batch`、`apply-exact`、`record-result` 命令。它们尚不存在；实现后必须能在没有打开浏览器、没有调用模型的情况下运行。导出包含简短 Markdown 任务摘要与结构化清单，放在私人导出目录。模型只接收选定批次需要的内容。

### 8.2 先处理作者已经写好的文字

对“改这段”比较三份内容：记录中的原文、当前目标分支的正文、作者替换稿。

- 目标区块与原文一致且位置唯一：精确应用作者替换稿。
- 目标正文已经包含同一修改：记录为已包含，避免重复应用。
- 原文有重名区块、位置不确定或当前内容已有重叠修改：展示原文、现文、作者稿；由编辑决定。模糊匹配不能自动写入。

直接修改先进入下一轮专用分支。AI 再处理批注与章节扩写，并对照作者修改检查，不能顺手把作者刚改好的措辞还原。若新的论证确实要求再次改动，呈现差异和理由。

### 8.3 批注、想法及处理回执

“下一轮处理”的批注进入本轮任务；“先记录”的想法供规划参考。一般作者身份不替代具体意图。来源中的网页文字、引文和未来可能接入的外部反馈都属于材料，不自动成为有权改变任务范围的指令。

每项回执至少说明：已应用、已被现文覆盖、待解决冲突、暂缓或撤回；已应用项附目标文件及提交/差异证据。只有写入候选源码并核验后才能标为“已整合”，生成一段聊天回复不算完成。“已整合”仍不等于“已发布”。

批次冻结后新增意见或新修订留给下一批。中途退出可以按批次 ID 恢复；重复运行不能重复插入同一修改。整合工具只写明确指定的专用工作分支/工作副本，拒绝 main、历史标签及冻结发行目录。它不调用 push、merge 或 publish。

### 8.4 预览与发布

整合后沿用既有候选审阅、Authoring Gate 和 Release Gate。已有明确发布授权时，常规检查、合并和部署不再逐步请求确认；本轮作者工作台的设计授权本身不包含这些操作。

## 9. 实施顺序与验收

以下工作包均为待授权的实施计划，由同一执行任务顺序推进；不要求每包结束都询问用户。先打通入口和保存，再扩展覆盖面。只有范围变化或关键技术假设失败需要集中说明。

| 包 | 交付 | 验收重点 | 依赖 |
| --- | --- | --- | --- |
| AW-01 入口与定位验证 | 带运行时的 Windows 启动器、快捷方式、协议跳转；一个真实章节的源码映射原型 | 冷启动无需终端；从网页打开正确章/节；陌生参数无写入副作用；代表段落映射可靠 | 设计批准 |
| AW-02 直接修改与保存 | 私人数据库、修订/撤销、侧栏编辑、保存状态 | 保存与重启后不丢；源仓库字节不变；重复段落和并发标签不误改；恢复包可用 | AW-01 |
| AW-03 私人预览 | 隔离 Quarto 副本、缓存、版本提示 | 修改能显示；失败不丢记录；非目标文字/链接/数学内容保持；旧构建不覆盖新状态 | AW-02 |
| AW-04 批注与随手记 | 段落/章节/跨项目记录、统一收件箱 | 不填复杂表单；自动带上下文；先记录与待处理有区别；过期位置能识别 | AW-02 |
| AW-05 下一轮整合 | 批次接口、三方比较、作者修改保护、处理回执 | 精确合并、冲突可见、幂等、恢复、新修订隔离、任务范围限制 | AW-03/04 |
| AW-06 两站完整接入 | 全部当前页面映射、旧链接/锚点兼容、安装卸载说明与本地试用包 | 两站切换及真实完整回路；正文/历史资产未变；无私人资料进入构建/包 | AW-05 |
| AW-07 入口上线 | 两站公共“作者模式”入口及构建标识 | 安装后从正式网站冷启动；正常读者浏览不受影响；线上旧链接检查通过 | 用户验收及独立技术发布授权 |

首轮只拿一章做技术验证，但完整功能交付须覆盖两站所有当前页面。复杂区块可以使用明确的降级路径；不能把“一章演示能用”报告为全站完成。

建议工作量比例：入口/打包与源码定位 30%，保存/恢复 20%，编辑/预览 20%，批注/整合 20%，两站验收与交付 10%。这是安排重点，不是未经实测的工时承诺。

## 10. 必须通过的完整场景

1. 关闭服务，从桌面打开工作台；从浏览器某章进入同一章和锚点；协议被限制时，粘贴页面地址仍能定位。首次安装与重启系统后均验证。
2. 修改普通段落，看到“已保存”；退出、重开、重新渲染，修改记录和草稿效果仍在。两个原仓库的正文及发行资产哈希未变。
3. 保存期间模拟写入失败，界面不误报；撤销后能恢复前一稿。两个标签页同时修改时不覆盖新修订。
4. 跨章留意见、记录全书想法，关机后仍可读；恢复备份后内容、来源快照及批次关系完整。
5. 相同句子在不同章节或同章重复，直接修改只作用于目标；前文插入段落后仍正确定位；目标重写后进入冲突处理。
6. 注释、链接、提示框、列表、公式、表格、代码和旧锚点经代表性及全量链接检查；源片段降级行为明确。桌面和窄窗口可操作。
7. 冻结一个批次后作者继续写新意见；Agent 整合旧批次不吞掉新意见。重复整合和中断恢复不重复应用。
8. 以测试分支模拟作者改字、AI 扩写、候选检查、逐条回执；整合结果可审阅，未调用发布。完成后恢复测试工作副本，保留真实私人记录。
9. 外部 URI、越界路径、无会话的写请求、预览脚本不能修改数据或源码；安装包和两站构建不含私人库、秘密或本机路径。
10. 已有网站构建、导航、下载、历史标签和资产保持兼容。公共入口上线后才验收正式网站跳转，不能以本地预览替代。

## 11. 已明确的取舍

- 先服务个人电脑上的写作；公开评论、云端同步、多人协同和后台模型运行不在范围。
- 不迁移正文到另一个内容系统，不新建通用 CMS，不为作者模式另造研究工作流框架。
- 浏览器原位编辑只覆盖可可靠映射的内容；支持范围扩大要有具体样本测试。
- 主手册与指南共用工具，正文版本和编辑授权分别管理。
- 快捷入口是首个工作包和必过验收项，不能等内容功能做完后再补。

## 12. 官方技术依据

核查日期：2026-10-18。下列资料确认可用机制；本设计中的组合、界面和验收标准是项目建议，不代表已有实现或已经测试。

- [Quarto 可视化编辑](https://quarto.org/docs/tools/vscode/visual-editor.html)：现成源码编辑能力；不等同于可直接编辑生成的网页。
- [Quarto 项目配置档](https://quarto.org/docs/projects/profiles.html)、[过滤器](https://quarto.org/docs/extensions/filters.html)：支持隔离配置和输出变换，不据此推断自动具备双向段落映射。
- [Windows URI activation](https://learn.microsoft.com/en-us/windows/apps/develop/launch/handle-uri-activation)、[Win32 应用注册](https://learn.microsoft.com/en-us/windows/win32/shell/app-registration)：启动入口与注册；打包模型不同，实现需分别验证，外部 URI 参数不可信。
- [FastAPI 本机服务启动机制](https://fastapi.tiangolo.com/deployment/manually/)、[Vite 静态构建](https://vite.dev/guide/build.html)：服务与预构建前端的职责。
- [PyInstaller 打包机制](https://pyinstaller.org/en/stable/operating-mode.html)：将应用及 Python 依赖打包；不会因此自动包含 Quarto。
- [Python sqlite3](https://docs.python.org/3/library/sqlite3.html)、[SQLite 备份接口](https://www.sqlite.org/backup.html)：事务存储和一致备份的实现依据。
